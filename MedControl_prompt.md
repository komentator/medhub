# Задача: разработка Windows-приложения MedControl

Ты — опытный senior-разработчик Windows-приложений и архитектор ПО. Необходимо разработать полноценное приложение **MedControl** для Windows 11 x64 — локальный менеджер приёма лекарств, дневник артериального давления/пульса и самочувствия.

Это должно быть **реальное готовое к ежедневному использованию приложение**, а не демонстрационный прототип.

---

## 1. Технологический стек

Использовать:

- C#
- .NET 8 LTS
- WPF
- SQLite
- NAudio — управление системной громкостью Windows
- ClosedXML — импорт/экспорт Excel `.xlsx`
- LiveCharts2 — графики
- Inno Setup — установщик `.exe`

Архитектура должна быть пригодна для дальнейшей публикации в Microsoft Store через MSIX.

Основная сборка: **x64**.

Не использовать:

- облачные базы данных;
- обязательный интернет;
- телеметрию;
- сторонние онлайн-сервисы;
- скрытые процессы;
- подозрительные механизмы автозапуска;
- скачивание исполняемых файлов;
- PowerShell-скрипты для установки;
- обфускацию без необходимости.

Все медицинские данные хранятся локально.

---

# 2. Язык и интерфейс

Интерфейс первой версии полностью на русском языке.

Архитектуру локализации построить через ресурсы, чтобы в будущем можно было добавить другие языки без переписывания интерфейса.

Стиль:

- простой;
- классический;
- практичный;
- хорошо читаемый;
- без лишних декоративных элементов;
- без перегруженности.

Не использовать авторизацию, пароль или PIN для входа в приложение.

---

# 3. Хранение данных

Основная БД:

```text
%LOCALAPPDATA%\MedControl\Data\
```

Использовать SQLite.

Данные должны сохраняться безопасно:

- транзакции;
- атомарные операции;
- миграции БД;
- защита от частично записанных данных;
- корректная обработка ошибок SQLite;
- отсутствие потери данных при штатном завершении/перезапуске.

Не выполнять полную `PRAGMA integrity_check` при каждом запуске.

Проверять целостность БД:

- при обнаружении признаков повреждения;
- по кнопке «Проверить базу данных» в настройках.

При обнаружении проблемы с БД нельзя молча удалять или исправлять данные.

# 4. Главное окно

Главное окно содержит:

1. блок активных напоминаний/ближайших приёмов;
2. график верхнего давления;
3. график нижнего давления;
4. график пульса;
5. график самочувствия;
6. статистику;
7. кнопку «Новое измерение»;
8. кнопку «Показать измерения».

Для текущего дня отображать **все запланированные приёмы лекарств**, отсортированные по времени.

Если лекарств много — использовать прокрутку.

Если активных напоминаний нет:

> Активных напоминаний нет

Настройки не размещать на главном экране. Все настройки находятся в отдельном разделе «Настройки».

---

# 5. Графики давления и пульса

Периоды:

- 7 дней;
- 30 дней;
- 3 месяца;
- 1 год;
- всё время.

По умолчанию: **30 дней**.

Для графиков можно выбрать:

- конкретный тонометр;
- все тонометры.

На графиках:

- отображать точки измерений;
- при наведении показывать дату, время, тонометр и значения;
- при клике по точке открывать соответствующее измерение для редактирования.

Статистика выбранного периода:

- среднее верхнее давление;
- среднее нижнее давление;
- средний пульс;
- минимальные значения;
- максимальные значения;
- количество измерений.

---

# 6. Самочувствие

Добавить отдельную систему оценки самочувствия по шкале **1–10**.

Пояснения:

- 1 — очень плохо;
- 5 — средне;
- 10 — отлично.

Оценка полностью необязательна.

Пользователь может создать её:

- после подтверждения приёма лекарства;
- после сохранения измерения давления;
- отдельно через кнопку «Оценить самочувствие».

Для выбора использовать **10 больших кнопок 1–10**.

При создании новой оценки дата и время автоматически берутся из системных часов Windows в момент выбора оценки.

Исторический ввод даты/времени для новой оценки не разрешён.

---

## 6.1. Редактирование самочувствия

Сохранённую оценку можно редактировать:

- изменить оценку;
- изменить комментарий.

Исходные дата и время оценки сохраняются.

Отдельно хранить дату/время последнего редактирования.

---

## 6.2. Комментарий

Комментарий необязателен.

Если пользователь не ввёл комментарий непосредственно в оценке самочувствия, но затем добавил комментарий к связанному:

- приёму лекарства;
- измерению давления;

то комментарий автоматически копируется в оценку самочувствия.

Если у оценки уже есть собственный комментарий — его нельзя автоматически заменять.

Если комментарий был автоматически перенесён, дальнейшие изменения исходного комментария **не синхронизируются**.

Если оценка связана сразу с несколькими записями и комментарий есть только у одной из них — перенести первый найденный непустой комментарий по времени.

---

## 6.3. Связи самочувствия

Отдельная оценка автоматически связывается с записями, произошедшими в пределах:

**15 минут до или после оценки.**

Если в этот интервал попадает несколько записей, оценка связывается **со всеми подходящими записями**.

Если связанная запись удалена:

- оценка самочувствия остаётся;
- связь с удалённой записью удаляется.

Если удаляется сама оценка:

- удаляется только оценка;
- связанные измерения и приёмы лекарств остаются.

Не хранить отдельное поле «Источник».

---

## 6.4. Время оценки

После подтверждения лекарства:

- сначала фиксируется приём;
- затем сразу предлагается оценить самочувствие;
- время оценки — фактическое время выбора оценки.

После измерения давления:

- измерение сохраняется;
- сразу предлагается необязательная оценка;
- время оценки — фактическое время выбора оценки.

---

## 6.5. График самочувствия

На главном экране отдельный график самочувствия.

Периоды те же:

- 7 дней;
- 30 дней;
- 3 месяца;
- 1 год;
- всё время.

Отображать все оценки, даже если их несколько в один день.

Статистика:

- средняя оценка;
- минимальная;
- максимальная;
- количество оценок.

Все оценки учитываются в статистике независимо от наличия связей.

---

## 6.6. Маркеры самочувствия на других графиках

На графиках давления и пульса отображать оценки самочувствия отдельными значками/маркерами.

Не изменять шкалу давления или пульса ради оценки 1–10.

Маркер отображается в собственной временной точке **даже если в этот момент нет измерения давления/пульса**.

При клике на маркер открывать только информационное окно без редактирования.

Информационное окно:

- дата;
- время;
- оценка 1–10;
- комментарий.

---

# 7. Таблицы истории

Создать раздел **«История»**.

Внутри:

- «Измерения»;
- «Приём лекарств»;
- «Самочувствие».

В таблицах «Измерения» и «Приём лекарств» добавить колонку:

**Самочувствие**

Если с одной записью связано несколько оценок — отображать все значения через запятую.

---

# 8. Лекарства

Для каждого лекарства:

- название — до 100 символов;
- назначение/описание — без ограничения длины;
- дозировка — до 100 символов;
- несколько времён приёма;
- без ограничения количества лекарств.

Примеры дозировки:

```text
1 таблетка
½ таблетки
10 мл
2 капсулы
```

---

## 8.1. Расписание

Два режима:

### Каждый день

Лекарство принимается ежедневно.

### По дням недели

Пользователь выбирает:

- Пн;
- Вт;
- Ср;
- Чт;
- Пт;
- Сб;
- Вс.

Можно выбрать несколько дней.

Для каждого времени допускается собственная дозировка.

---

## 8.2. Продолжительность

Варианты:

### Постоянно

Нет конечной даты.

### По расписанию

Указать:

- дату начала;
- дату окончания.

Лекарство можно отключить или удалить.

Удаление лекарства не удаляет историю его приёмов.

---

# 9. История приёма лекарств

История должна хранить **снимок данных на момент события**:

- название лекарства;
- назначение;
- дозировку;
- запланированное время;
- фактическое время;
- статус;
- способ подтверждения;
- комментарий;
- связанное самочувствие.

Изменение лекарства в будущем не должно изменять старую историю.

Не хранить историю изменений расписания или названия лекарства.

Для фактического приёма:

- дата и время запланированного события;
- дата и время фактического подтверждения — отдельно.

После подтверждения статус нельзя редактировать.

Комментарий можно:

- добавить;
- изменить;
- удалить.

---

# 10. Напоминания

В назначенное время показывать **собственное окно MedControl**, а не стандартное Windows Toast.

Окно:

- всегда поверх остальных;
- крупный читаемый текст;
- нельзя закрыть крестиком;
- пользователь должен нажать:
  - «Принял»
  - или «Отложить 15 минут».

Показывать отдельно каждое лекарство:

- название;
- назначение;
- дозировка.

---

## 10.1. Группировка

События, наступившие в пределах **15 минут**, можно объединять в одно окно.

Для группы одна кнопка:

**«Принял»**

Она подтверждает все представленные события.

Каждое событие имеет уникальный ID и может быть подтверждено только один раз.

В окне отображаются только ещё не подтверждённые события.

---

## 10.2. Отложить

«Отложить 15 минут»:

- переносит все события текущей группы;
- через 15 минут окно появляется снова;
- снова воспроизводится звук.

Если появляются новые события, они обрабатываются отдельно согласно общей логике группировки.

---

## 10.3. Особая логика отмены отложенной группы

Если группа была отложена, а пользователь затем вручную подтверждает одно из её событий через историю:

- вся отложенная группа отменяется;
- все остальные события группы автоматически получают статус **«Принял»**;
- для всех автоматически подтверждённых событий устанавливается одно и то же фактическое время — момент ручного подтверждения группы.

В истории обязательно сохранять **способ подтверждения**.

---

# 11. Звук и системная громкость

При напоминании воспроизводить звук.

Если напоминание не подтверждено:

- повторить звук через 10 минут.

Интервал 10 минут не настраивается пользователем.

При активном напоминании приложение через NAudio снижает **Master Volume текущего устройства вывода Windows**.

Не изменять баланс левого/правого канала.

Диапазон настройки:

**0–50%**

По умолчанию:

**10%**

При первом активном напоминании сохранить исходную громкость.

Пока существуют неподтверждённые события, громкость остаётся сниженной.

При подтверждении всех активных событий восстановить исходную громкость.

Отложенное напоминание не восстанавливает громкость.

Если пользователь вручную изменил громкость Windows во время активного напоминания:

- приложение не должно перезаписывать это изменение;
- не должно после завершения напоминания ошибочно восстанавливать старое значение поверх ручного изменения.

Все ошибки управления громкостью записывать в технический журнал.

---

# 12. Пропущенные лекарства

Настраиваемый период до статуса «Пропущено»:

- 15 минут;
- 30 минут;
- 1 час;
- 2 часа;
- 3 часа;
- 6 часов.

По умолчанию:

**1 час**.

После перезапуска компьютера приложение должно обнаруживать пропущенные события.

После выхода компьютера из сна/гибернации также выполнять пересчёт.

Пропущенное событие можно:

- оставить «Пропущено»;
- отметить как «Принял позже».

При этом сохраняется:

- запланированное время;
- фактическое время позднего подтверждения.

---

# 13. Внеплановый приём

Добавить возможность:

**«Внеплановый приём»**

Пользователь выбирает:

- лекарство;
- дозировку;
- фактическое время.

Внеплановый приём не изменяет расписание и не закрывает следующий запланированный приём.

---

# 14. Комментарии лекарств

После подтверждения пользователь может нажать:

**«Добавить комментарий»**

Комментарий:

- необязательный;
- без ограничения длины;
- можно редактировать;
- можно удалить.

---

# 15. Дневник давления и пульса

Поддерживать до **10 тонометров**.

Каждый тонометр имеет:

- название до 50 символов.

Тонометр можно изменить или удалить.

Удаление тонометра не удаляет исторические измерения.

Не создавать автоматически «Тонометр 1».

Если тонометров нет и пользователь нажимает «Новое измерение»:

- показать понятное сообщение;
- предложить перейти в настройки и добавить тонометр.

---

# 16. Новое измерение

Кнопка:

**«Новое измерение»**

При текущем измерении дата и время автоматически берутся из системных часов Windows **в момент сохранения**.

Пользователь не может изменить их.

Поля:

- тонометр;
- верхнее давление;
- нижнее давление;
- пульс;
- комментарий;
- самочувствие.

---

# 17. Историческое измерение

Через историю/отдельный режим можно создать историческое измерение.

Для него разрешить вручную выбрать:

- дату;
- время;
- тонометр;
- значения;
- комментарий.

---

# 18. Проверка давления и пульса

Диапазоны:

### Верхнее

50–300 мм рт. ст.

### Нижнее

30–200 мм рт. ст.

### Пульс

20–250 уд/мин.

Разрешить специальное значение:

```text
0 / 0
```

Запретить:

```text
120 / 0
0 / 80
```

Верхнее давление должно быть строго больше нижнего, кроме специального случая `0/0`.

Пульс `0` разрешён независимо от давления.

Не делать медицинских диагнозов и не выводить сообщения вроде «опасно», «гипертония» и т.п.

---

# 19. Редактирование измерений

После сохранения:

- дату нельзя менять;
- время нельзя менять;
- тонометр можно менять;
- значения можно менять;
- комментарий можно менять/удалять.

Хранить:

**«Последнее изменение»**

Но изменять его только если реальные данные действительно изменились.

Версионирование измерений не требуется.

---

# 20. История измерений

Колонки:

```text
Дата | Время | Тонометр | Верхнее | Нижнее | Пульс | Самочувствие | Комментарий
```

Комментарии показывать только если они существуют.

Фильтры:

- период;
- тонометр;
- текстовый поиск.

Поиск осуществляется по названию тонометра.

---

# 21. История лекарств

Поиск по названию лекарства.

Фильтры статуса:

- Все;
- Принял;
- Принял позже;
- Пропущено;
- Внеплановый приём.

Массовое удаление разрешено только после обязательного подтверждения и предупреждения.

---

# 22. Корзина

Для измерений и приёма лекарств использовать общую **«Корзину»**.

Разделы:

- Измерения;
- Приём лекарств.

Хранить удалённые записи бессрочно до ручной очистки.

Для каждой записи:

- исходные данные;
- дата удаления;
- время удаления.

Действия:

- Восстановить;
- Удалить навсегда;
- Очистить корзину.

Удаление навсегда и очистка корзины требуют подтверждения.

После восстановления хранить дату/время восстановления.

Полная история восстановления не нужна.

Для корзины измерений и лекарств не нужны поиск и фильтры.

Сортировка — по дате.

---

# 23. Корзина самочувствия

Для оценок самочувствия использовать **отдельную корзину**.

Удалённая оценка:

- не удаляется физически сразу;
- попадает в корзину;
- может быть восстановлена;
- может быть удалена навсегда;
- корзина может быть очищена.

Удаление/очистка требуют подтверждения.

Корзина самочувствия не объединяется с корзиной измерений и лекарств.

Период:

- 7 дней;
- 30 дней;
- 3 месяца;
- 1 год;
- всё время;
- произвольный период.

Можно выбрать:

- измерения;
- приём лекарств;

- графики;

# 28. Условие создания ежедневного backup

Backup создаётся после того, как **последний запланированный приём лекарства за текущий день** получил статус именно:

**«Принял»**

Статусы:

- «Принял позже»;
- «Пропущено»

не считаются успешным завершением дня.

Если в этот день вообще нет запланированных лекарств — backup не создаётся.

Если последний приём был пропущен, а позже пользователь отметил его «Принял», backup создаётся в этот момент.

Если пользователь вообще не подтвердил последний приём — backup за этот день не создаётся.

Следующая успешная отметка «Принял» в другой день создаёт одну актуальную копию текущего состояния.

Не создавать отдельные копии задним числом за пропущенные дни.
